    一、它是什么¶

    一款面向学生与青年工程师的公路桥涵水文计算工具。核心价值不是"又一个 P-Ⅲ 计算器"，而是：

    1. 把规范里要人工翻的表格内置进软件——径流厚度 h 大表、ψ、z、β、γ、δ、暴雨分区、Cv 平均值，全部可查可插值；
    2. 白盒化——每一步都标出公式、条号、页码、取哪一档，结果可复核；
    3. 可追溯——每次计算自动进日志（输入 / 采用值 / 结果 / 依据），可导出存档；
    4. 可无人值守（v0.11.0 新增）——计算内核可被命令行脚本驱动，批量出成果、批量回归验证。

    与《桥位设计计算系统》QW2.0 的关系¶

    QW2.0（高冬光 / 甘肃紫光智能交通 / 西安软通）是商业闭源软件，老师反馈其痛点是：经验公式与各种指数不内置，要人工查表。泓算就是冲着这个痛点做的。

    对标结果（教材《桥涵水文》第五版例 3-1-1，32 年系列）：

    项目 泓算 QW2.0 偏差
    Q₁% 4824 4840 −0.33%
    Q₂% 4301 4311 −0.23%
    Q₀.₃₃% 5647 5666 −0.34%
    矩法 Q̄ 1838.9 1839 一致

    三个设计频率偏差均 ≤0.35%，且该算例已固化为回归测试。

    CLI 用法（v0.11.0 新增）¶

    cd 桥涵水文项目/app
npm run build:cli                                   # 构建 dist/cli/hongsuan.js（esbuild 单文件零依赖）

npm run cli -- compute <工程.json> -o <结果.json>    # 单工程无头计算
npm run cli -- batch <工程目录> -o <结果目录>         # 批量计算目录内全部工程
npm run cli -- verify [算例库目录]                    # 算例回归验证（默认 examples/）
    • 退出码：0 全过 ｜ 1 存在计算失败 ｜ 2 输入非法 —— 可直接挂 CI / 设计院批处理流程

    • 错误以 JSON 行输出到 stderr，field 字段可直接映射到界面输入框

    四、对标 HEC-RAS 的工程实践（v0.11.0 / v0.11.1 新增）¶

    4.1 缘起：一次真实的 HEC-RAS 使用体验¶

    2026-09-25 实际安装并使用美国陆军工程兵团 HEC-RAS 7.0.1（水利行业国际主流一维/二维水动力学软件）， 下载官方例题包（407 MB，7 大类 1126 个文件），逐字节解析其工程文件格式，并尝试 COM 自动化批处理。

    实测结论（正面）：HEC-RAS 值得学的三件事——

    1. 工程 = 文件夹 + 一组人可读的文本文件：.prj 索引 + .g01 几何 + .f01 流量 + .p01 方案 + .r01 输出， 方案（Plan）只存引用不复制数据，跑 10 个方案每个方案文件只有几 KB；
    2. 例题即文档：安装后单独提供 7 大类例题，每个都带完整输入与已知正确输出；
    3. 输出自描述：.r01 开头完整回显断面几何、糙率、流量、边界条件——10 年后拿着结果文件 alone 就能复原输入。

    实测结论（反面，即泓算的机会）：

    # 尝试 结果
    1 PowerShell COM Compute_CurrentPlan($false,$true) ❌ ByRef 类型不兼容
    2 Python win32com 动态调度 ❌ SAFEARRAY 类型不匹配
    3 gencache 强类型包装 ❌ "Subscript out of range"（文档签名 2 参 vs 实际 3 参）
    4 VARIANT 显式包装 ❌ pywin32 新版已移除 VARIANT 类
    5 纯值调用（签名已对） ❌ VBA 内部错误 1000009（6.2 工程在 7.0.1 下不兼容）
    6 Project_SaveAs 升级格式重算 ❌ 同错
    7 命令行 Ras.exe -p xx -compute yy ❌ 进程挂起无输出（无官方批处理文档）
    8 GUI + SendKeys 模拟点击 ❌ 按键未送达

    结论：具备逆向能力的开发者，2 小时内无法实现一次无人值守计算。 错误信息只有一句裸 VBA 码，无字段、无定位、无建议；6.2 的工程在 7.0.1 下直接崩。 ——这正是泓算可以建立代差优势的地方。以下四项改进全部由此而来。

    4.2 无头计算管线 app/src/core/compute.ts¶

    把界面 10 个计算模块的公式与守卫，从 DOM 点击处理函数中抽成纯函数：

    computeAll(state) → ComputeReport   // schema: hongsuan-result@1
    • 输出含完整输入快照（inputs）——对应 HEC-RAS .r01 的可追溯性思想；
    • 模块级容错：单个模块出错不拖垮整份报告（批处理时尤为重要）；
    • 每模块标注规范依据（条号/表号），成果可序列化、可 diff。

    4.3 CLI 批处理 app/src/cli/main.ts¶

    compute / batch / verify 三个子命令 + 退出码约定（0/1/2），esbuild 打包为单文件零依赖。 HEC-RAS 做不到的无人值守计算，泓算三行命令批量出成果。

    4.5 结构化错误体系 app/src/core/errors.ts（v0.11.1）¶

    HEC-RAS 的全部错误信息是裸 VBA 码 "Subscript out of range"。泓算的错误带完整结构：

    { "code": "E_INPUT_RANGE", "field": "state.nodata.rdH", "value": 380,
  "message": "径流厚度 h=380mm 超出表B-9第Ⅲ区Ⅳ土范围",
  "suggestion": "请检查暴雨分区选择，或改用推理公式其它经验公式",
  "normRef": "JTG C30-2015 附录B 表B-9" }

    错误码：E_INPUT_MISSING / E_INPUT_FINITE / E_INPUT_RANGE / E_INPUT_TYPE / E_DEPENDENCY / E_CONVERGE / E_SCHEMA / E_INTERNAL。 field 精确到字段路径（如 state.scour.scBcj），界面可据此把输入框标红，CLI 可据此输出机读 JSON ——这是 HEC-RAS 永远做不到的"错误指到输入框"。

    4.6 工程文件版本迁移器 app/src/core/migrate.ts（v0.11.1）¶

    HEC-RAS 6.2 的工程在 7.0.1 下直接崩。泓算的工程文件 schema 已升级到 hongsuan-project@2：

    • 打开 @1 旧工程 → 沿迁移链静默升级，不报错、不丢用户数据，并在结果里留痕 migratedFrom；
    • 迁移链每步是一个独立小函数（from / to / note / migrate），可单测、可扩展（@2→@3 继续往后接）；
    • 无法识别的 schema 抛结构化 E_SCHEMA（含已知迁移链提示），绝不静默吞掉。

    五、计算正确性：五层证据链¶

    1. Φ 值独立交叉：与 scipy 在 627 点网格上比对，100% < 1e-6
    2. 解析恒等式：Cs=2 时 Φ(1%) = ln(100)−1 = 3.60517，精确成立
    3. 矩法交叉：与 numpy 比对 < 5e-12
    4. 工程算例端到端：T1~T4、k3+685 涵洞（29.22）、贵州（59.34）、教材例 3-1-1
    5. 权威 Φ 表抽验：在表值舍入范围内
    6. 冲止流速闭合校验：行近流速 v = E·d̄^(1/6)·hp^(2/3) 与 64-1 公式严格自洽（测试中双重验证）
    7. 算例回归库（v0.11.0 新增）：6 算例 12 项检查，一键可复现，最大偏差 0.014%

    发现并纠正的公开资料勘误（测试基准以手算复核为准）： - 某题库 T1：Σd²=885350 加错（实为 785250） - CSDN 某算例：校核 Φ(0.1%, Cs=1.5)=4.58 有误（实为 5.2335） - 教材例 3-1-1：Σ=58587 与其自身 Q̄=1839 矛盾（58846/32=1838.9，疑印刷勘误）

    环境坑（本机特有，记下来省得再踩）¶

    • PowerShell 执行策略拦 npm.ps1 → 用 npm.cmd
    • .ps1 含中文必须存 UTF-8 BOM，否则按 GBK 解码成乱码
    • PowerShell *> 重定向输出是 UTF-16，Python 读取需 encoding="utf-16"
    • WorkBuddy shell 泄漏 ELECTRON_RUN_AS_NODE=1 → 验证 Electron 前必须 $env:ELECTRON_RUN_AS_NODE=$null; $env:NODE_OPTIONS=$null
    • build_desktop 删目录会触发沙箱批量删除确认 → 先用 PowerShell Remove-Item 清 electron_dist/unpacked 与 dist/泓算桌面版-*
    • 改完 UI 必须重跑 make_offline / build_desktop，否则离线版缺新控件 → E2E 挂
    • E2E 点击：页面布局会因控件显隐变化，必须切换后再取 boundingBox；用 locator.click({position}) 比 page.mouse.click 稳

    5.3 方法 A：P-III 频率适线（规范 6.2，模块核心）¶

    流程八步（软件主流程）：

    1. 资料审查（6.2.1 ✅）：同一洪水类型、独立随机、人为影响还原、首几项重点考证、系列不宜少于 30 年且应有历史洪水调查成果。→ 软件做输入数据合理性检查（如系列长度提示）。
    2. 系列插补/延长/转换（6.2.2 ✅）：断面与水文站面积差 <20% 且 ≤1000 km²、暴雨分布均匀、无分洪滞洪时，按面积比转换。
    3. 经验频率（6.2.3 ✅）：
    4. 连序系列：Pm = m/(n+1) × 100%（m 为从大到小的序位）
    5. 不连序系列（含特大洪水）两种处理（见 参考资料\教材与例题资料.md §3，已核实）：
      • 独立处理法：特大洪水 PM = M/(N+1)；实测系列 Pm = m/(n+1)；重复流量取小值
      • 条件概率法：实测期一般洪水 Pm = PM,l + (1−PM,l) × (m−l)/(n−l+1) （N 为考证期年数，a 为特大洪水项数，l 为其中出现在实测期内的项数）
    6. 参数初估（6.2.5 ✅）：可采用求矩适线法、三点适线法、绘线读点补矩法计算均值 Q̄、变差系数 Cv、偏态系数 Cs 的初算值。
    7. 矩法公式（教材标准 ⚠️ 按高冬光《桥涵水文》核实）： Q̄ = (1/n)·ΣQi；Ki = Qi/Q̄ Cv = √[ Σ(Ki−1)² / (n−1) ]（无偏） Cs = n·Σ(Ki−1)³ / [(n−1)(n−2)]（无偏，仅作初估）
    8. 理论频率曲线（6.2.4 ✅）：宜采用皮尔逊 Ⅲ 型曲线；特殊情况经论证可用其他线型。
    9. 适线（6.2.5 ✅）：点绘理论频率曲线与经验点据比较，不吻合则调整 Cv、Cs 直至基本吻合。工程惯例 Cs 取 Cv 的 2~4 倍整数倍试凑（⚠️ 惯例值）。
    10. 软件的杀手锏交互：海森机率格纸上经验点据 + 理论曲线实时联动，Cv/Cs 滑块拖动即时重绘。
    11. 设计值（6.2.6 ✅ 规范原式）： Qp = Q̄ · (1 + Φp · Cv) 其中 Φp 为离均系数，由 Cs 和设计频率 p 查 P-III Φ 值表（或数值计算 Γ 分布分位数）。Qp 也可写为 Qp = Kp·Q̄，Kp = 1+Φp·Cv 为模比系数。
    12. 合理性论证（1.0.5 ✅）：与上下游、邻站、地区统计参数对比（均值、Cv 沿流域渐变规律）。

    数值实现要点： - Φp 求解 = P-Ⅲ 分布（三参数 Γ 分布）的分位数计算，JS 中用不完全 Gamma 函数数值反解，或内置 Φ 值表插值（教材附表，精度 0.01） - 海森机率格纸：横坐标按标准正态分布变换（P=0.01%~99.9%），ECharts 自定义坐标轴实现 - 目估适线之外可加"优化适线"（最小二乘/绝对偏差最小），作为进阶功能

    5.4 方法 B：历史洪水位法（规范 6.3）¶

    1. 历史洪水流量（6.3.1 ✅ 规范原式）： 稳定均匀流河段（顺直、比降均一、断面规整）： Q = Ac·vc + At·vt，vc = (1/nc)·Rc^(2/3)·I^(1/2)，vt = (1/nt)·Rt^(2/3)·I^(1/2) （河槽/河滩分算；宽深比 >10 时水力半径 R 可用平均水深代替；n 为糙率、I 为水面比降） 非均匀流河段用试算法推水面线（6.3.1-4）。
    2. 经验频率（6.3.2 ✅）：由老居民记述/文献考证定序位，按 6.2.3 公式计算。
    3. 推算设计流量（6.3.3 ✅）：
    4. 历史洪水流量不宜少于 2 次；Cv、Cs 应符合地区分布规律
    5. 多次历史洪水可在海森机率格纸上定出经验频率曲线时 → 按适线法求 Q̄、Cv、Cs
    6. 定不出曲线时：参照地区资料选定 Cv、Cs，按 Q̄Ti = QTi / (1 + ΦT·Cv) 求平均流量（ΦT 为重现期 T 年的离均系数），再按 6.2.6 推算 Qp

    5.5 方法 C：无资料地区（规范 6.4）¶

    • 6.4.1（✅）：无资料地区，可按地区经验公式及水文参数求算设计流量；求算的设计流量应有历史洪水流量的验证。
    • 6.4.2（✅）：汇水面积 < 100 km² 的河流，可按推理公式计算；公式中的参数和指数，采用各地区编制的暴雨径流图表值。
    • 6.4.3（✅）：小桥涵、路基及特殊地区的设计流量计算，尚应符合第 9~11 章。

    具体公式形式（规范正文只给原则，公式细节出自教材《桥涵水文》/《公路设计手册·桥涵水文》分册 ⚠️ 待对照核实）：

    推理公式（水科院型，公路科研所采用）： Qp = 0.278 · (ψ · Sp / τⁿ) · F - Sp：雨力（mm/h），查地区暴雨等值线图（按设计频率取值） - τ：汇流时间（h）；n：暴雨衰减指数 - ψ：洪峰径流系数；F：汇水面积（km²）

    径流厚度法（公路科研所暴雨径流公式，小流域涵洞常用）： Qp = φ · (h − z)^(5/3) · F^(2/3) · β · γ · δ - φ：地貌系数（按地形、汇水面积、主河沟坡度查表） - h：径流厚度（mm）；z：植被或坑洼滞留的径流厚度（mm） - β：洪峰传播流量折减系数；γ：降雨不均匀折减系数；δ：湖泊/小水库调节折减系数

    面积比拟法（6.2.2 同型，转换/比拟通用）： Q设 = Q参 · (F设/F参)ⁿ - 面积修正指数 n（✅ 论文引规范）：大中河流 0.5~0.7；<100 km² 小河流 >0.7；面积差 ≤3% 时 n=1

    5.6 相关但不属本模块（边界说明）¶

    • 设计水位（6.5 ✅）：由水位—流量关系曲线按 Qp 反推 + 水面比降换算到桥位断面；复杂河段试算法推水面线。→ 属后续"桥孔/桥面高程"模块输入。
    • 设计洪水过程线（6.6 ✅）：同倍比放大法，kg = Qp/Q（典型洪峰流量）。→ 远期。
