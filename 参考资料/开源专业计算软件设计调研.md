# 开源专业计算软件设计调研（2026-09-22）

> 应卓庆要求：去 GitHub 看工业软件/专业计算软件的设计思路与方法，指导泓算后续架构。

## 一、调研对象（真实开源项目）

| 项目 | 是什么 | 关键架构事实 |
|---|---|---|
| **HEC-RAS / HEC-HMS**（美国陆军工程兵团 HEC） | 全球最权威的河流水力/水文计算软件，公有领域免费 | 几何/流量/边界条件是**文件化的数据模型**，与求解器引擎严格分离；GUI 只是数据模型的编辑器；RAS Mapper 做 GIS 结果可视化 |
| **Calcpad**（Proektsoft，MIT，C#） | 开源"计算书即程序"工程计算软件（Mathcad 替代品） | 仓库按 **Core（计算核）/ Wpf（桌面）/ WebApi / Cli / OpenXml（docx 导出）/ Tests** 分项目——计算核与 UI 物理隔离；内建**单位制**（SI/Imperial/USCS）；**HTML 表单自动生成**做参数输入；结果自动汇编为 HTML 报告并导出 Word/PDF |
| **RAS-Commander / HEC-Commander**（CLB Engineering，Python） | HEC-RAS/HMS 的开源自动化 API（GitHub 活跃） | **TDD 用官方示例项目做测试夹具**（可重复演示）；"可复现交付物"（每次输出都能在 HEC GUI 里人工核验）；**LLM Forward 十戒**：专业责任第一、LLM 加速但不替代工程师判断、多层次可验证性（GUI 核验 + 可视输出 + 代码审计） |

## 二、提炼出的 8 条设计原则

1. **计算核与 UI 严格分离**（HEC、Calcpad 共同点）——核可以被 CLI、Web、桌面多种外壳复用，也才能独立做单元测试。
2. **数据模型先行**：把"一次计算"建模为纯数据（参数+系列+选项），求解器只吃数据吐数据，天然获得撤销/重算/存档能力。
3. **回归测试锚定权威算例**（RAS-Commander 手法）：每个计算方法至少锚定 1~2 个公开算例的已知数值，改一行代码跑一遍。
4. **查表数据与公式统一接口**（CoolProp 式思路）：表值进 JSON、查表函数带插值与出处标注，调用方无感。
5. **单位制显式化**：Calcpad 内建单位系统；小软件至少做到"输入框旁标单位 + 换算锚点测试"（泓算 0.278=1/3.6 量纲锚点即是此思路）。
6. **白盒化与可核验**：公式出处、参数含义、计算过程全部可见——恰是泓算对国产商业软件黑盒的差异化点，与 RAS-Commander 的 human-in-the-loop 精神一致。
7. **报告即产品**：Calcpad 把"自动生成计算书"作为核心功能而非附属——泓算的 Word 导出方向正确，下一步让计算书完全由计算过程数据驱动生成（而非手工拼字段）。
8. **表单 schema 驱动**：每个方法声明参数 schema（名称/单位/范围/默认值/出处），表单 UI、校验、计算书三处自动生成，避免三处不同步。

## 三、对照泓算现状

**已符合**：① 核与 UI 分离（`src/core` 与 `web/index.html` 内核同构）；② 权威算例回归（42 测试：解析锚点+scipy 交叉+公开算例 k3+685/贵州/湖南）；③ 白盒化（公式出处、Φ 值算法、合理范围检查）；④ 报告即产品（Word 计算书）。

**差距与下一步**（按优先级）：
1. **Vite/TS 工程化**（沙箱 npm 受限，待用户环境）——消灭"内核两处同构维护"的手工同步成本，这是当前最大架构债。
2. **参数 schema 化**：方法 B/C 的参数表先做成 JSON（名称/单位/范围/出处），UI 与计算书共用。
3. **查表数据 JSON 化**：径流厚度 h 大表（18 分区×6 土类×3 频率×3 历时）拿到教材后进 `data/` 目录，线性插值 + 出处标注。
4. **远期**：方法插件化（新方法=一个 schema+一个核函数+一组算例）、断面数据导入（结合筑鉴 XML 经验）。
